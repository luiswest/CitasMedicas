Cómo publicar Citas Médicas en Internet, paso a paso

Guía para estudiantes que nunca han desplegado una aplicación. Explica qué hace cada paso, por qué se hace, qué debería ver en pantalla y qué hacer si algo sale mal. Al terminar, cualquier persona podrá abrir la aplicación desde su navegador o su teléfono.

Nivel: principiante Tiempo total: 2 a 4 horas Costo: US$0 Versión 2 · 20 de noviembre de 2026
Los planes gratuitos cambianLo que esta guía dice sobre límites, tarjetas y nombres de botones corresponde a noviembre de 2026. Si una pantalla del proveedor se ve distinta, busque la opción con un nombre parecido; los conceptos no cambian.

Cómo usar esta guía

Recorra las secciones en orden: cada una supone que terminó la anterior. Si se pierde, vuelva al último paso que funcionó.

Los bloques de comandos

Los comandos aparecen en recuadros oscuros con un botón Copiar. La etiqueta de la esquina dice dónde se ejecuta cada uno, y es importante respetarla:

SU PC · POWERSHELL SERVIDOR (VM) · UBUNTU SQL LO QUE DEBERÍA VER
  • SU PC · POWERSHELL: la terminal de su computadora con Windows. Lo más práctico es usar la terminal integrada de VS Code (menú Terminal → New Terminal), que ya se abre en la carpeta del proyecto.
  • SERVIDOR (VM) · UBUNTU: comandos para la computadora en la nube, después de conectarse a ella por SSH (se explica en la opción A).
  • LO QUE DEBERÍA VER (recuadro claro con borde punteado): no es un comando. Es un ejemplo de la respuesta esperada, para comparar con lo que muestra su pantalla.

Reglas para copiar comandos

  • Lo que aparece en MAYÚSCULAS_CON_GUIONES_BAJOS, como TU_USUARIO o IP_PUBLICA, debe reemplazarlo por su propio valor antes de presionar Enter.
  • El texto gris que empieza con # es un comentario. La terminal lo ignora, así que puede copiarlo junto con el comando sin problema.
  • En PowerShell, una línea que termina con un acento grave ` continúa en la línea siguiente. Copie el bloque completo.
  • Si un comando muestra un error en rojo, no siga con el siguiente paso. Busque el mensaje en Problemas comunes.
  • Pegar en la terminal: Ctrl+V en PowerShell y VS Code; clic derecho en la terminal SSH si Ctrl+V no funciona.

Conceptos básicos (lea esto primero)

Desplegar tiene su propio vocabulario. Estos son los términos que aparecen en la guía, con una comparación cotidiana:

Desplegar (deploy)
Llevar la aplicación de su computadora a un servidor conectado a Internet para que otras personas la usen. Como pasar de cocinar en casa a abrir un restaurante.
Servidor
Una computadora encendida las 24 horas en un centro de datos, que responde a las peticiones que llegan por Internet.
Máquina virtual (VM)
Una computadora «simulada» dentro de un servidor grande. Usted la controla como si fuera suya, pero vive en la nube.
Imagen de Docker
Un paquete que contiene su programa y todo lo que necesita para correr (PHP, Apache, librerías). Es la receta y los ingredientes ya empacados.
Contenedor
Una imagen en ejecución. De una misma imagen pueden correr varios contenedores. Si la imagen es la receta, el contenedor es el plato servido.
Dockerfile
Archivo de texto con las instrucciones para construir una imagen: «parte de PHP 8.5, instala esto, copia este código…».
Docker Compose
Herramienta que levanta varios contenedores a la vez y los conecta, a partir de un archivo docker-compose.yml. Hoy usted ya la usa en desarrollo.
Puerto
Un número que identifica cada servicio dentro de una computadora. La web usa el 80 (HTTP) y el 443 (HTTPS). Si la IP es la dirección del edificio, el puerto es el número de apartamento.
Variable de entorno
Un valor de configuración que se entrega al programa desde fuera, sin escribirlo en el código. Por ejemplo DB_HOST=db.
Secreto
Una variable de entorno que nadie debe ver: contraseñas, llaves de JWT. Nunca se sube a GitHub.
Dirección IP
El número que identifica a una computadora en Internet, por ejemplo 152.70.12.34.
Dominio y DNS
Un nombre fácil de recordar (citas.ejemplo.com) que el sistema DNS traduce a una IP. Como la agenda de contactos del teléfono.
HTTPS y certificado
HTTPS cifra la comunicación entre el navegador y el servidor. Requiere un certificado, que Let's Encrypt emite gratis. Es lo que muestra el candado del navegador.
Proxy inverso
Un programa que recibe las peticiones y las reenvía al servicio correcto. En esta guía Nginx y Caddy cumplen ese papel. Como la recepcionista que dirige a cada visitante a su oficina.
PaaS
«Plataforma como servicio»: usted entrega el código o la imagen y el proveedor se encarga del servidor. Render, Cloud Run y Azure Container Apps son PaaS.
Base de datos gestionada
Un MySQL que administra otra empresa (Aiven, en esta guía). Usted solo recibe la dirección, el usuario y la contraseña.
SSH
Forma segura de abrir una terminal en una computadora remota. Se usa para controlar la VM.
Repositorio y rama (Git)
El repositorio es el historial del proyecto; una rama es una línea de trabajo paralela. Se crea una rama despliegue para no afectar main.
Logs
Los mensajes que escribe un programa mientras corre. Son la primera fuente para averiguar por qué algo falla.

Cómo está hecha su aplicación

Citas Médicas está dividida en capas, y cada capa corre en su propio contenedor. La idea de desplegarla es conservar esa separación también en Internet:

Ejemplo de lo que ocurre cuando alguien inicia sesión:

  1. El navegador envía usuario y contraseña a https://su-sitio/api/auth/login, es decir, a la capa de Presentación.
  2. Nginx, dentro de Presentación, ve que la ruta empieza con /api y la reenvía a Negocio.
  3. Negocio le pide a Datos las credenciales del usuario y le agrega una llave secreta (X-Internal-Key) para demostrar que la petición viene de Negocio.
  4. Datos consulta MySQL y devuelve el resultado.
  5. Negocio verifica la contraseña, genera el token JWT y la respuesta vuelve por el mismo camino.

Desarrollo vs. producción: por qué hay que cambiar archivos

La configuración actual funciona bien en su computadora (desarrollo), pero tiene atajos que no sirven en Internet (producción). Estas son las diferencias y cómo las resuelven los archivos nuevos:

En desarrollo (hoy)Por qué no sirve en InternetQué hacen los archivos nuevos
Docker «presta» las carpetas Data/src y Business/src desde su disco (volúmenes).El servidor no tiene acceso a su disco, así que el contenedor arrancaría sin código.Los nuevos Dockerfile copian el código dentro de la imagen.
Las contraseñas están en Business/.env y Data/.env, que están subidos a GitHub.Cualquiera con acceso al repositorio o a la imagen vería las contraseñas.Un script de arranque (docker-entrypoint.sh) crea el .env con valores que usted configura en el hosting.
Angular llama a http://localhost:9090/api.En el navegador del usuario, localhost es su propia computadora, no el servidor.Angular llama a /api en su mismo sitio, y Nginx lo reenvía a Negocio.
La capa de Presentación no tiene contenedor (está comentada en el compose).No habría quien sirva las pantallas.Se agregan Presentation/Dockerfile y una configuración de Nginx.
La capa de Datos y MySQL publican sus puertos (8080 y 3307).Cualquiera en Internet podría leer o borrar datos sin pasar por Negocio.Solo Presentación queda pública, y Datos exige la llave INTERNAL_KEY.
Apache escucha siempre en el puerto 80.Algunos hostings asignan otro puerto mediante la variable PORT.El script de arranque ajusta el puerto automáticamente.
La conexión a MySQL no indica puerto ni cifrado.Las bases de datos en la nube usan otros puertos y exigen conexión cifrada (TLS).config.php, conexion.php y eloquent.php aceptan puerto y TLS.
El Dockerfile verifica el instalador de Composer con un código fijo.Composer cambia ese instalador cada cierto tiempo y el build fallaría.Se toma Composer de su imagen oficial.
Su entorno de desarrollo sigue funcionandoLos archivos nuevos usan por defecto los mismos valores de hoy, así que docker compose up y ng serve siguen igual. Una sola diferencia: si no define la variable KEY, Negocio inventa una llave temporal y tendrá que iniciar sesión de nuevo cada vez que reinicie los contenedores.

⏱ 10 minutos
¿Por qué GitHub?Los hostings descargan el código desde GitHub para construir las imágenes. En la opción A, la VM también lo descarga de ahí.

Paso 4 · Probar la versión de producción en su computadora

⏱ 15 a 25 minutos (el primer build es lento)
¿Por qué probar en local?Si algo falla, es mucho más fácil corregirlo en su computadora que en un servidor remoto. Lo que funcione aquí con docker-compose.prod.yml funcionará igual en la VM de la opción A.
  1. Detenga los contenedores de desarrollo. Ambos compose usan los mismos nombres de contenedor (base_datos, web_datos…), así que no pueden correr a la vez: 
    Su PC · PowerShelldocker compose down

    Su PC · PowerShellCopy-Item .env.prod.example .env.prod

    Su PC · PowerShellfunction Nueva-Llave {
  $b = New-Object byte[] 32
  [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b)
  ($b | ForEach-Object { $_.ToString('x2') }) -join ''
}
"JWT_KEY      = $(Nueva-Llave)"
"INTERNAL_KEY = $(Nueva-Llave)"

    Su PC · PowerShelldocker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build

Paso 5 · Elegir dónde publicar

Hay dos formas de publicar contenedores gratis, y esta guía cubre ambas:

  • Una máquina virtual (opción A). Usted alquila (gratis) una computadora en la nube y hace exactamente lo mismo que en el paso 4. Es lo más parecido a su entorno actual. Requiere usar SSH y algunos comandos de Linux.
  • Un PaaS (opciones B, C y D). Usted entrega el código o las imágenes y el proveedor los ejecuta. No administra ningún servidor, pero MySQL debe ir aparte (en Aiven), porque los PaaS borran el disco de los contenedores al reiniciarlos.

Opción A · Oracle Cloud Always Free (máquina virtual)

⏱ 60 a 90 minutos

Oracle regala, sin fecha de vencimiento, máquinas virtuales ARM de hasta 4 procesadores y 24 GB de RAM. Usted instalará Docker en una de ellas y levantará los mismos contenedores del paso 4.

Antes de empezar
  • Oracle pide una tarjeta de crédito o débito para verificar su identidad. Puede hacer un cargo temporal que luego se reversa. Mientras use solo recursos marcados como Always Free, no cobra.
  • Si su región se queda sin capacidad, al crear la VM verá el error «Out of capacity». Intente más tarde o con menos recursos (1 procesador y 6 GB).
  • Oracle puede recuperar VMs gratuitas que pasan 7 días casi sin uso. Si la VM desaparece, se vuelve a crear con estos mismos pasos.

A.1 · Crear la cuenta y la máquina virtual

  1. Cree la cuenta en oracle.com/cloud/free con el botón Start for free. En Home Region elija una región cercana, por ejemplo US East (Ashburn) o Mexico Central (Querétaro). La región no se puede cambiar después. La activación puede tardar unos minutos y llega por correo.
  2. Cree la instancia. En el menú ☰ vaya a Compute → Instances y presione Create instance. Complete así:
    • Name: citas-medicas
    • Image and shape → Edit:
      • Change image → Canonical Ubuntu → versión 24.04.
      • Change shape → Ampere → VM.Standard.A1.Flex, con 2 OCPUs y 12 GB de memoria. Debe ver la etiqueta Always Free-eligible.
    • Networking: deje que cree una red nueva (Create new virtual cloud network) con subred pública, y verifique que esté marcado Assign a public IPv4 address.
    • Add SSH keys: elija Generate a key pair for me y presione Save private key. Se descarga un archivo como ssh-key-2026-11-20.key. Guárdelo en una carpeta segura, por ejemplo C:\Users\SU_USUARIO\.ssh\.
    Presione Create. En 1 o 2 minutos el estado cambia de Provisioning a Running.
  3. Anote la IP pública. En la página de la instancia, en Instance access, copie la Public IP address, por ejemplo 152.70.12.34. La usará varias veces.
La llave SSH es como la llave de su casaSin el archivo .key no puede entrar a la VM, y Oracle no lo guarda. No lo pierda ni lo suba a GitHub.

A.2 · Abrir los puertos 80 y 443

¿Qué está haciendo?Por seguridad, Oracle bloquea todo el tráfico que llega a la VM excepto SSH (puerto 22). Para que se pueda visitar la aplicación hay que permitir el puerto 80 (HTTP) y el 443 (HTTPS). Existen dos «puertas» que abrir: el firewall de Oracle (Security List) y el firewall de Ubuntu (iptables, en A.3).
  1. En la página de la instancia, haga clic en el nombre de la Subnet (sección Primary VNIC).
  2. En Security Lists, abra Default Security List for …
  3. Presione Add Ingress Rules y complete: Source CIDR 0.0.0.0/0 (significa «desde cualquier lugar»), IP Protocol TCP, Destination Port Range 80. Presione + Another Ingress Rule y repita con el puerto 443. Guarde con Add Ingress Rules.

A.3 · Conectarse a la VM por SSH

  1. Proteja el archivo de la llave. Windows le da permisos demasiado abiertos y SSH se niega a usarlo con el error «UNPROTECTED PRIVATE KEY FILE». Estos comandos dejan que solo su usuario pueda leerlo: 
    Su PC · PowerShellcd $HOME\.ssh
icacls .\ssh-key-2026-11-20.key /inheritance:r
icacls .\ssh-key-2026-11-20.key /grant:r "$($env:USERNAME):(R)"
    Cambie el nombre del archivo por el de su llave.
  2. Conéctese. El usuario de las VMs Ubuntu en Oracle es ubuntu: 
    Su PC · PowerShellssh -i $HOME\.ssh\ssh-key-2026-11-20.key ubuntu@IP_PUBLICA
    La primera vez preguntará «Are you sure you want to continue connecting (yes/no)?». Escriba yes y Enter. 
    Lo que debería verWelcome to Ubuntu 24.04 LTS (GNU/Linux ... aarch64)
...
ubuntu@citas-medicas:~$
    El texto ubuntu@citas-medicas:~$ indica que ahora está escribiendo dentro de la VM. Desde aquí, los comandos llevan la etiqueta «Servidor (VM)». Para salir escriba exit.
  3. Actualice el sistema y abra los puertos en el firewall de Ubuntu. sudo ejecuta el comando como administrador: 
    Servidor (VM) · Ubuntusudo apt update && sudo apt upgrade -y

¿Qué significan los códigos HTTP más comunes?
  • 200 OK: todo bien.
  • 401 Unauthorized: falta el token o no es válido (no ha iniciado sesión).
  • 403 Forbidden: el servidor entendió la petición, pero no la permite.
  • 404 Not Found: la ruta no existe.
  • 500 Internal Server Error: el programa falló; revise los logs de Negocio o Datos.

<?php
namespace App\Services;

use GuzzleHttp\ClientInterface;
use GuzzleHttp\Client;
use Psr\Http\Message\ResponseInterface;

/**
 * Cliente HTTP hacia la capa de DATOS.
 *
 * Cambio para despliegue: si existe INTERNAL_KEY en el .env, se envía en la
 * cabecera X-Internal-Key. La capa de datos (cuando también tiene INTERNAL_KEY)
 * rechaza con 403 cualquier petición que no la traiga, de modo que aunque el
 * hosting obligue a que la capa de datos tenga URL pública, solo la capa de
 * negocio puede consumirla. Sin INTERNAL_KEY se comporta igual que antes.
 */
final class DataService {
    private ClientInterface $client;
    public function __construct(object $config) {
        $headers = ['Accept' => 'application/json'];
        $internalKey = $_ENV['INTERNAL_KEY'] ?? '';
        if ($internalKey !== '') {
            $headers['X-Internal-Key'] = $internalKey;
        }

        $this->client = new Client([
            'base_uri' => rtrim($config->api_data, '/') . '/',
            'timeout' => $config->timeout,
            'connect_timeout' => $config->timeout,
            'http_errors' => false,
            'headers' => $headers
        ]);
    }
    public function get(string $path, array $query = []): ResponseInterface {
        return $this->client->request('GET', ltrim($path, '/'),
            ['query' => $query]);
    }
    public function post(string $path, string $body): ResponseInterface {
        return $this->client->request('POST', ltrim($path, '/'),
            ['body' => $body,
             'headers' => ['Content-Type' => 'application/json']
             ]);
    }
    public function put(string $path, string $body): ResponseInterface {
        return $this->client->request('PUT', ltrim($path, '/'),
            ['body' => $body,
             'headers' => ['Content-Type' => 'application/json']
             ]);
    }
    public function delete(string $path): ResponseInterface {
        return $this->client->request('DELETE', ltrim($path, '/'));
    }
}

INTERNAL_KEY="$(printf '%s' "$INTERNAL_KEY" | tr -d '\r\n')"

#  DB_SSL_CA      -> ruta a un archivo .pem ya montado (Render, Cloud Run)
#  DB_SSL_CA_PEM  -> contenido PEM en la variable
#  DB_SSL_CA_B64  -> contenido PEM en base64 (útil en Azure / PowerShell)

    printf '%s' "$DB_SSL_CA_B64" | tr -d '\r\n ' | base64 -d > "$CA_FILE"

    DB_SSL_CA="$CA_FILE"
    DB_SSL="${DB_SSL:-true}"
fi

ENV_FILE=/var/www/html/.env

    echo "DB_PORT='${DB_PORT:-3306}'"
    echo "DB_USER='${DB_USER:-root}'"

    [ -n "$DB_SSL_VERIFY" ] && echo "DB_SSL_VERIFY='${DB_SSL_VERIFY}'"

} > "$ENV_FILE"

    echo "[datos] API protegida con X-Internal-Key"

    rm -f "$CONF"
    echo "[datos] AVISO: INTERNAL_KEY no definida; la API acepta cualquier petición." >&2

# ==========================================================================
#  Citas Médicas - despliegue de PRODUCCIÓN en una VM (Oracle Cloud, GCP, ...)
#
#  Uso:
#    cp .env.prod.example .env.prod      # y editar los valores
#    docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
#
#  Separación en capas (cada red solo une capas vecinas):
#    Internet -> proxy(Caddy) -> webpresentacion -> webnegocio -> webdatos -> db
#              red_publica        red_presentacion   red_negocio   red_datos
#  Solo el proxy publica puertos; ninguna otra capa es accesible desde fuera.
# ==========================================================================
name: citasmedicas

services:
  db:
    image: mysql:9.7
    container_name: base_datos
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD_FILE: /run/secrets/db_password
      MYSQL_DATABASE: citas_medicas
    volumes:
      - ./db_dump:/docker-entrypoint-initdb.d:ro   # solo se ejecuta con el volumen vacío
      - mysql_data:/var/lib/mysql
    secrets:
      - db_password
    networks:
      - red_datos
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "--silent"]
      interval: 10s
      timeout: 5s
      retries: 12
      start_period: 40s

  webdatos:
    container_name: web_datos
    build:
      context: .
      dockerfile: ./Data/Dockerfile
    restart: unless-stopped
    environment:
      DB_HOST: db
      DB_PORT: "3306"
      DB_USER: root
      DB_NAME: citas_medicas
      DB_PASSWORD_FILE: /run/secrets/db_password
      INTERNAL_KEY: ${INTERNAL_KEY:?Defina INTERNAL_KEY en .env.prod}
    secrets:
      - db_password
    depends_on:
      db:
        condition: service_healthy
    networks:
      - red_datos
      - red_negocio

  webnegocio:
    container_name: web_negocio
    build:
      context: .
      dockerfile: ./Business/Dockerfile
    restart: unless-stopped
    environment:
      KEY: ${JWT_KEY:?Defina JWT_KEY en .env.prod}
      API_DATA: http://webdatos/api
      API_TIMEOUT: "10"
      JWT_TTL: ${JWT_TTL:-3600}
      INTERNAL_KEY: ${INTERNAL_KEY}
      # Orígenes que pueden llamar a la API directamente (app Android/Capacitor).
      # La web no lo necesita porque pasa por el proxy de nginx (mismo dominio).
      CORS_ALLOWED_ORIGINS: ${CORS_ALLOWED_ORIGINS:-http://localhost,https://localhost,capacitor://localhost}
    depends_on:
      - webdatos
    networks:
      - red_negocio
      - red_presentacion

  webpresentacion:
    container_name: web_presentacion
    build:
      context: ./Presentation
      dockerfile: Dockerfile
    restart: unless-stopped
    environment:
      BUSINESS_URL: http://webnegocio
    depends_on:
      - webnegocio
    networks:
      - red_presentacion
      - red_publica

  proxy:
    image: caddy:2-alpine
    container_name: proxy_https
    restart: unless-stopped
    environment:
      # Dominio público. Con un dominio real (o <ip>.sslip.io) Caddy obtiene
      # el certificado HTTPS de Let's Encrypt automáticamente.
      # Vacío -> ":80" (solo HTTP por el puerto 80).
      DOMAIN: ${DOMAIN:-:80}
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - webpresentacion
    networks:
      - red_publica

networks:
  red_publica:
  red_presentacion:
    internal: true
  red_negocio:
    internal: true
  red_datos:
    internal: true

volumes:
  mysql_data:
  caddy_data:
  caddy_config:

secrets:
  db_password:
    file: ./db_password.txt
