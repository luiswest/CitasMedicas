Despliegue gratuito de Citas Médicas en contenedores

Paso a paso para poner la aplicación en línea con hosting gratuito, usando los contenedores que ya tiene el proyecto y manteniendo la separación en capas: Presentación → Negocio → Datos → Base de datos.

Angular 22 + Nginx Slim 4 / PHP 8.5 (Negocio) Slim 4 / Eloquent (Datos) MySQL Generada: 19 de noviembre de 2026
Antes de empezarLos planes gratuitos cambian con frecuencia. Las condiciones descritas aquí (límites, tarjeta requerida, suspensión por inactividad) corresponden a noviembre de 2026: confírmelas en la página de precios de cada proveedor antes de crear cuentas.

Resumen

La aplicación ya está dividida en contenedores, pero la configuración actual está pensada para desarrollo local. Para publicarla hay que hacer tres cosas:

  1. Aplicar los archivos de reemplazo de la carpeta despliegue/sobrescribir/. No se modificó ningún archivo original: usted decide cuándo copiarlos.
  2. Elegir un hosting. Esta guía propone cuatro opciones gratuitas. Todas mantienen cada capa en su propio contenedor.
  3. Configurar los secretos (llave JWT, llave interna y contraseña de la BD) como variables de entorno del hosting, nunca dentro del repositorio.
Recomendada

A · Oracle Cloud Always Free

Una VM con Docker Compose: los 4 contenedores tal cual, sin «dormir». Requiere tarjeta solo para verificar.

 Más sencilla

B · Render + Aiven

Tres servicios web desde GitHub con un blueprint. Sin tarjeta. Los servicios se duermen tras 15 min sin uso.

 Más robusta

C · Google Cloud Run + Aiven

Contenedores serverless con capa gratuita amplia. Requiere cuenta de facturación (tarjeta).

 Para estudiantes

D · Azure for Students

Container Apps con Datos y Negocio privados. Usa el crédito estudiantil, sin tarjeta.

Arquitectura en capas

El navegador solo habla con la capa de Presentación. Nginx sirve Angular y reenvía /api/* a Negocio; Negocio valida el JWT y llama a Datos; Datos es la única capa que conoce la base de datos. Así se conserva la separación y se eliminan los problemas de CORS en la web.

Al revisar la configuración actual aparecen estos puntos, que impedirían o harían inseguro el despliegue:

La única diferencia: si no define KEY, Negocio genera una llave temporal y los tokens se invalidan al reiniciar el contenedor.

Opción A · Oracle Cloud Always Free (VM con Docker Compose)

Es la opción que más se parece a su entorno actual: una máquina virtual Linux donde corren los cuatro contenedores con docker compose. La capa gratuita «Always Free» incluye instancias Ampere A1 (ARM) de hasta 4 OCPU y 24 GB de RAM en total, sin vencimiento.

Tenga en cuentaOracle pide una tarjeta para verificar identidad (no cobra mientras use recursos Always Free). Las instancias gratuitas con uso muy bajo durante 7 días pueden ser reclamadas; para una demo activa no suele ser problema. Si su región no tiene capacidad A1, intente más tarde o use VM.Standard.E2.1.Micro (1 GB RAM, agregue swap).
  1. Cree la cuenta en oracle.com/cloud/free. Elija una «home region» cercana (p. ej. US East (Ashburn) o Mexico Central (Querétaro)): no se puede cambiar después.
  2. Cree la instancia: Compute → Instances → Create instance.
    • Image: Canonical Ubuntu 24.04
    • Shape: VM.Standard.A1.Flex, 2 OCPU y 12 GB de memoria
    • Networking: VCN nueva con subred pública y Assign public IPv4 address
    • SSH keys: Generate a key pair y descargue la llave privada (.key)
  3. Abra los puertos 80 y 443 en la nube: Networking → Virtual cloud networks → su VCN → Security Lists → Default → Add Ingress Rules: origen 0.0.0.0/0, TCP, puertos destino 80 y 443.
  4. Conéctese por SSH desde PowerShell: 
    PowerShellssh -i C:\ruta\ssh-key.key ubuntu@IP_PUBLICA
  5. Abra los puertos en el firewall de Ubuntu. Las imágenes de Oracle traen reglas iptables que bloquean todo excepto SSH: 
    VMsudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
sudo netfilter-persistent save
  6. Instale Docker: 
    VMcurl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
newgrp docker
docker compose version
  7. Descargue el proyecto. Si el repositorio es privado, use un Personal Access Token de GitHub como contraseña: 
    VMgit clone -b despliegue https://github.com/TU_USUARIO/TU_REPO.git citas
cd citas
  8. Cree los secretos de producción: 
    VM# Contraseña nueva de MySQL (sin salto de línea)
printf '%s' "$(openssl rand -hex 16)" > db_password.txt
chmod 600 db_password.txt

cp .env.prod.example .env.prod
sed -i "s/^JWT_KEY=.*/JWT_KEY=$(openssl rand -hex 32)/" .env.prod
sed -i "s/^INTERNAL_KEY=.*/INTERNAL_KEY=$(openssl rand -hex 32)/" .env.prod

# Dominio gratuito con sslip.io: IP 152.70.12.34 -> 152-70-12-34.sslip.io
IP=$(curl -s ifconfig.me)
sed -i "s/^DOMAIN=.*/DOMAIN=${IP//./-}.sslip.io/" .env.prod
cat .env.prod      # revise los valores
    Si tiene dominio propio, cree un registro A hacia la IP pública y use ese nombre en DOMAIN. También sirve DuckDNS (gratis).
  9. Construya y levante los contenedores (el primer build en ARM tarda de 5 a 10 minutos): 
    VMdocker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f proxy   # verá cuando obtenga el certificado
    Abra https://IP-CON-GUIONES.sslip.io.
  10. Para actualizar después de nuevos commits: 
    VMgit pull
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
  11. Respalde la BD de vez en cuando: 
    VMdocker exec base_datos sh -c 'exec mysqldump -uroot -p"$(cat /run/secrets/db_password)" citas_medicas' > respaldo_$(date +%F).sql
Sobre db_dump/scripts.sqlMySQL ejecuta el script solo la primera vez, con el volumen mysql_data vacío. Para reinicializar la BD desde cero: docker compose -f docker-compose.prod.yml down -v. Esto borra todos los datos.
Alternativa con el mismo procedimientoGoogle Cloud ofrece una VM e2-micro gratuita (regiones us-west1, us-central1 y us-east1). Tiene 1 GB de RAM: cree 2 GB de swap antes de compilar Angular. Los pasos 5 a 11 son iguales, salvo que el firewall se abre en VPC network → Firewall.

Base de datos gestionada gratis · Aiven for MySQL (para B, C y D)

En los PaaS el disco de los contenedores es efímero, así que MySQL no puede correr ahí como contenedor. Aiven ofrece un plan gratuito de MySQL sin tarjeta, compatible con los procedimientos almacenados del script.

  1. Cree el servicio: en console.aiven.io elija Create service → MySQL → Free plan y una región cercana a su hosting (p. ej. do-nyc o aws-us-east-1). Espere unos minutos a que quede Running.
  2. Anote los datos de conexión en Overview → Connection information: Host, Port, User (avnadmin) y Password. Descargue el CA certificate como ca.pem en la raíz del proyecto (ya está ignorado en git).
  3. Cree la base: pestaña Databases → Create database → citas_medicas.
  4. Importe el script. Sin instalar el cliente de MySQL, con Docker y desde la raíz del proyecto: 
    PowerShelldocker run --rm -v "${PWD}\db_dump:/dump" -v "${PWD}\ca.pem:/ca.pem" mysql:8.4 `
  sh -c 'mysql -h HOST_AIVEN -P PUERTO_AIVEN -u avnadmin -p"PASSWORD_AIVEN" --ssl-mode=VERIFY_CA --ssl-ca=/ca.pem citas_medicas < /dump/scripts.sql'
  5. Variables que usará la capa de Datos en cualquiera de las opciones B, C o D: 
    DB_HOST=HOST_AIVEN
DB_PORT=PUERTO_AIVEN
DB_USER=avnadmin
DB_PASSW=PASSWORD_AIVEN
DB_NAME=citas_medicas
DB_SSL=true
DB_SSL_CA=/ruta/al/ca.pem      # o DB_SSL_CA_PEM (contenido) o DB_SSL_CA_B64 (base64)
Límites del plan gratuito1 GB de almacenamiento y un único nodo, sin garantías de disponibilidad. Aiven puede apagar servicios gratuitos que pasen mucho tiempo sin uso; se reactivan desde la consola. Otras alternativas gratuitas compatibles con MySQL: Azure Database for MySQL (12 meses con cuenta gratuita) y Filess.io.

Opción B · Render (3 servicios web) + Aiven

Render construye cada Dockerfile directamente desde GitHub. El archivo render.yaml crea los tres servicios de una vez.

Limitaciones del plan Free
  • Cada servicio se duerme tras 15 minutos sin tráfico; el primer acceso tarda alrededor de un minuto, y puede ser una cadena de tres arranques (Presentación → Negocio → Datos). Por eso API_TIMEOUT=60.
  • Los servicios gratuitos no reciben tráfico por red privada, así que la capa de Datos tiene URL pública. Queda protegida por INTERNAL_KEY: sin la cabecera responde 403.
  • Hay 750 horas de instancia gratis al mes por workspace, compartidas entre los servicios. Como duermen sin uso, alcanzan para una demo.
  1. Prepare la BD en Aiven (sección anterior).
  2. Ajuste la rama en render.yaml: cambie branch: main por la rama que subió (p. ej. despliegue) en los tres servicios. Haga commit y push.
  3. Cree el blueprint: en dashboard.render.com elija New → Blueprint, conecte GitHub y seleccione el repositorio. Render leerá render.yaml y pedirá los valores marcados sync: false: DB_HOST, DB_PORT y DB_PASSW de Aiven.
  4. Suba el certificado de Aiven: servicio citas-datos → Environment → Secret Files → Add, nombre ca.pem, pegue el contenido. Quedará en /etc/secrets/ca.pem, la ruta que ya usa DB_SSL_CA.
  5. Verifique las URLs reales de cada servicio. Si Render agregó un sufijo (p. ej. citas-datos-x7k2.onrender.com), corrija:
    • citas-negocio → API_DATA=https://URL-REAL-DATOS/api
    • citas-medicas → BUSINESS_URL=https://URL-REAL-NEGOCIO (sin /api ni barra final)
    y haga Manual Deploy → Deploy latest commit en los servicios modificados.
  6. Abra la aplicación en https://citas-medicas.onrender.com (o la URL asignada).

Opción C · Google Cloud Run + Aiven

Cloud Run ejecuta contenedores bajo demanda y su capa gratuita mensual (2 millones de solicitudes, 180 000 vCPU-segundo y 360 000 GiB-segundo) sobra para un proyecto académico. Requiere una cuenta de facturación con tarjeta; configure una alerta de presupuesto para evitar cargos.

  1. Prepare el proyecto de Google Cloud: cree un proyecto en console.cloud.google.com, asócielo a una cuenta de facturación y cree un presupuesto de US$1 con alertas (Billing → Budgets & alerts). Instale gcloud CLI y ejecute: 
    PowerShellgcloud init
gcloud services enable run.googleapis.com secretmanager.googleapis.com
  2. Construya y publique las imágenes en Docker Hub (cuenta gratuita). Las imágenes no contienen secretos: el .env se genera al arrancar. 
    PowerShell · raíz del proyectodocker login
docker build --platform linux/amd64 -f Data/Dockerfile     -t TU_USUARIO/citas-datos:1.0 .
docker build --platform linux/amd64 -f Business/Dockerfile -t TU_USUARIO/citas-negocio:1.0 .
docker build --platform linux/amd64 -t TU_USUARIO/citas-web:1.0 ./Presentation
docker push TU_USUARIO/citas-datos:1.0
docker push TU_USUARIO/citas-negocio:1.0
docker push TU_USUARIO/citas-web:1.0
  3. Guarde los secretos en Secret Manager y dé acceso a la cuenta de servicio de Cloud Run: 
    PowerShell"PASSWORD_AIVEN" | gcloud secrets create db-passw --data-file=-
gcloud secrets create aiven-ca --data-file=ca.pem
$jwt = -join ((1..64) | % { '{0:x}' -f (Get-Random -Max 16) })
$jwt | gcloud secrets create jwt-key --data-file=-
$INTERNAL = -join ((1..64) | % { '{0:x}' -f (Get-Random -Max 16) })

$PN = gcloud projects describe (gcloud config get-value project) --format="value(projectNumber)"
gcloud projects add-iam-policy-binding (gcloud config get-value project) `
  --member="serviceAccount:$PN-compute@developer.gserviceaccount.com" `
  --role="roles/secretmanager.secretAccessor"
    Guarde el valor de $INTERNAL: se usa en Datos y en Negocio. PowerShell agrega un salto de línea al final de los secretos, pero los entrypoints lo eliminan.
  4. Despliegue la capa de Datos: 
    PowerShellgcloud run deploy citas-datos --image docker.io/TU_USUARIO/citas-datos:1.0 `
  --region us-central1 --allow-unauthenticated --max-instances 2 `
  --set-env-vars "DB_HOST=HOST_AIVEN,DB_PORT=PUERTO_AIVEN,DB_USER=avnadmin,DB_NAME=citas_medicas,DB_SSL=true,DB_SSL_CA=/secrets/ca.pem,INTERNAL_KEY=$INTERNAL" `
  --set-secrets "DB_PASSW=db-passw:latest,/secrets/ca.pem=aiven-ca:latest"

$DATOS = gcloud run services describe citas-datos --region us-central1 --format="value(status.url)"
  5. Despliegue la capa de Negocio: 
    PowerShellgcloud run deploy citas-negocio --image docker.io/TU_USUARIO/citas-negocio:1.0 `
  --region us-central1 --allow-unauthenticated --max-instances 2 `
  --set-env-vars "API_DATA=$DATOS/api,API_TIMEOUT=30,JWT_TTL=3600,INTERNAL_KEY=$INTERNAL" `
  --set-secrets "KEY=jwt-key:latest"

$NEGOCIO = gcloud run services describe citas-negocio --region us-central1 --format="value(status.url)"
  6. Despliegue la capa de Presentación: 
    PowerShellgcloud run deploy citas-web --image docker.io/TU_USUARIO/citas-web:1.0 `
  --region us-central1 --allow-unauthenticated --max-instances 2 `
  --set-env-vars "BUSINESS_URL=$NEGOCIO"
    La URL que muestra el comando (https://citas-web-…run.app) es la de la aplicación.
Por qué Datos tiene acceso públicoHacerla privada en Cloud Run exige ingress interno con una VPC o autenticación IAM entre servicios, y ambas cambian el código o agregan costo. La llave INTERNAL_KEY cumple la misma función: Datos rechaza con 403 cualquier petición que no venga de Negocio.

Opción D · Azure for Students (Container Apps) + Aiven

Con el correo institucional se obtienen US$100 de crédito anual sin tarjeta (azure.microsoft.com/free/students). Container Apps tiene además una asignación gratuita mensual, y permite que Datos y Negocio sean totalmente privados: solo Presentación tiene ingress externo y llega a Negocio por la red interna del entorno.

  1. Publique las imágenes en Docker Hub (igual que el paso 2 de la opción C).
  2. Prepare la CLI: 
    PowerShellaz login
az extension add --name containerapp --upgrade
az provider register --namespace Microsoft.App
az provider register --namespace Microsoft.OperationalInsights
az group create -n rg-citas -l eastus
az containerapp env create -n env-citas -g rg-citas -l eastus
  3. Datos (ingress interno): 
    PowerShell$INTERNAL = -join ((1..64) | % { '{0:x}' -f (Get-Random -Max 16) })
$CA = [Convert]::ToBase64String([IO.File]::ReadAllBytes("$PWD\ca.pem"))
az containerapp create -n citas-datos -g rg-citas --environment env-citas `
  --image docker.io/TU_USUARIO/citas-datos:1.0 --target-port 80 --ingress internal `
  --min-replicas 0 --max-replicas 1 `
  --secrets "db-passw=PASSWORD_AIVEN" "aiven-ca=$CA" "internal-key=$INTERNAL" `
  --env-vars DB_HOST=HOST_AIVEN DB_PORT=PUERTO_AIVEN DB_USER=avnadmin DB_NAME=citas_medicas `
             DB_SSL=true DB_PASSW=secretref:db-passw DB_SSL_CA_B64=secretref:aiven-ca `
             INTERNAL_KEY=secretref:internal-key
  4. Negocio (también interno, porque la web le llega a través de Nginx): 
    PowerShell$JWT = -join ((1..64) | % { '{0:x}' -f (Get-Random -Max 16) })
az containerapp create -n citas-negocio -g rg-citas --environment env-citas `
  --image docker.io/TU_USUARIO/citas-negocio:1.0 --target-port 80 --ingress internal `
  --min-replicas 0 --max-replicas 1 `
  --secrets "jwt-key=$JWT" "internal-key=$INTERNAL" `
  --env-vars API_DATA=http://citas-datos/api API_TIMEOUT=30 JWT_TTL=3600 `
             KEY=secretref:jwt-key INTERNAL_KEY=secretref:internal-key
  5. Presentación (ingress externo): 
    PowerShellaz containerapp create -n citas-web -g rg-citas --environment env-citas `
  --image docker.io/TU_USUARIO/citas-web:1.0 --target-port 80 --ingress external `
  --min-replicas 0 --max-replicas 1 `
  --env-vars BUSINESS_URL=http://citas-negocio
az containerapp show -n citas-web -g rg-citas --query properties.configuration.ingress.fqdn -o tsv
Cuide el créditoMantenga --min-replicas 0. Al terminar el curso, elimine todo con az group delete -n rg-citas.

Primer usuario administrador

scripts.sql crea los roles y las especialidades, pero ningún usuario. Las contraseñas se validan con password_verify, así que el usuario debe guardarse con un hash de password_hash:

PowerShell# 1) Generar el hash (cambie la contraseña)
docker run --rm php:8.5-cli php -r "echo password_hash('MiClaveSegura!', PASSWORD_DEFAULT), PHP_EOL;"
SQL-- 2) Insertarlo (rol 1 = Administrador)
INSERT INTO usuarios (username, password, rol_id, activo)
VALUES ('admin', 'HASH_GENERADO', 1, 1);
-- Si su lógica lo requiere, agregue también el registro en la tabla administradores.

Para ejecutar el SQL: en la opción A use docker exec -it base_datos sh -c 'mysql -uroot -p"$(cat /run/secrets/db_password)" citas_medicas'; en Aiven, el mismo docker run mysql:8.4 de la importación, sin la redirección del archivo y con -it.

App móvil (Android / Capacitor)

La app Android usa environment.android.ts, que hoy apunta a http://10.0.2.2:9090/api. Para usar el servidor publicado, cámbielo a la URL pública de Presentación (Nginx reenvía /api a Negocio):

Presentation/src/environments/environment.android.tsexport const environment = {
    servidor: 'https://SU-DOMINIO-PUBLICO/api'
};

Después ejecute pnpm run build:android. El origen de la WebView (http://localhost) ya está permitido en el CORS de Negocio (variable CORS_ALLOWED_ORIGINS). Con HTTPS ya no hace falta cleartext: true en capacitor.config.ts, aunque puede dejarlo mientras siga probando en local.

Verificación

Reemplace APP por la URL pública de Presentación y DATOS por la URL de Datos (opciones B y C):

PowerShell# La SPA responde
curl.exe -I https://APP/
# Una ruta de Angular no da 404 (fallback a index.html)
curl.exe -I https://APP/login
# El proxy llega a Negocio: sin token debe responder 401
curl.exe -i https://APP/api/medicos
# Login de punta a punta (Presentación -> Negocio -> Datos -> BD)
curl.exe -i -X POST https://APP/api/auth/login -H "Content-Type: application/json" -d "{\"username\":\"admin\",\"password\":\"MiClaveSegura!\"}"
# Datos NO debe atender peticiones directas: debe responder 403
curl.exe -i https://DATOS/api/medicos

Checklist de seguridad antes de publicar

  • Una KEY (JWT) nueva, de 64 caracteres aleatorios, distinta de la de Business/.env.
  • Una INTERNAL_KEY configurada igual en Negocio y en Datos.
  • Una contraseña de MySQL nueva; nunca 12345.
  • .env.prod, ca.pem y las llaves SSH fuera del repositorio.
  • Solo Presentación (o Caddy) expone puertos a Internet.
  • HTTPS activo: así el JWT no viaja en texto plano.
  • Valorar desactivar los detalles de error en producción: hoy addErrorMiddleware(true, …) muestra trazas al cliente. Puede hacerse más adelante con una variable APP_DEBUG.
  • Alertas de presupuesto (Cloud Run) o control del crédito (Azure).
  • Un respaldo de la BD antes de cada cambio de esquema.

#!/bin/sh
# ==========================================================================
#  Entrypoint de la capa de NEGOCIO
#  - Ajusta el puerto de Apache a $PORT (los PaaS lo asignan dinámicamente)
#  - Genera /var/www/html/.env a partir de variables de entorno
#    (así los secretos no quedan dentro de la imagen ni en el repositorio)
# ==========================================================================
set -e

PORT="${PORT:-80}"
sed -ri "s/^Listen [0-9]+/Listen ${PORT}/" /etc/apache2/ports.conf
sed -ri "s/<VirtualHost \*:[0-9]+>/<VirtualHost *:${PORT}>/" /etc/apache2/sites-enabled/000-default.conf

# Permite pasar la llave por archivo (Docker secrets): KEY_FILE=/run/secrets/jwt_key
if [ -z "$KEY" ] && [ -n "$KEY_FILE" ] && [ -f "$KEY_FILE" ]; then
    KEY="$(tr -d '\r\n' < "$KEY_FILE")"
fi
# Quita saltos de línea que algunos gestores de secretos agregan al final
KEY="$(printf '%s' "$KEY" | tr -d '\r\n')"
INTERNAL_KEY="$(printf '%s' "$INTERNAL_KEY" | tr -d '\r\n')"
if [ -z "$KEY" ]; then
    KEY="$(head -c 48 /dev/urandom | base64 | tr -d '\n=+/')"
    echo "[negocio] AVISO: no se definió KEY; se generó una llave temporal." >&2
    echo "[negocio]        Los tokens dejarán de ser válidos al reiniciar el contenedor." >&2
fi

ENV_FILE=/var/www/html/.env
{
    echo "KEY='${KEY}'"
    echo "API_DATA='${API_DATA:-http://webdatos/api}'"
    echo "API_TIMEOUT='${API_TIMEOUT:-5}'"
    echo "JWT_TTL='${JWT_TTL:-3600}'"
    [ -n "$CORS_ALLOWED_ORIGINS" ] && echo "CORS_ALLOWED_ORIGINS='${CORS_ALLOWED_ORIGINS}'"
    [ -n "$INTERNAL_KEY" ] && echo "INTERNAL_KEY='${INTERNAL_KEY}'"
    true
} > "$ENV_FILE"
chown www-data:www-data "$ENV_FILE"
chmod 640 "$ENV_FILE"

echo "[negocio] Escuchando en el puerto ${PORT}; capa de datos: ${API_DATA:-http://webdatos/api}"
exec docker-php-entrypoint "$@"
Business/src/Services/DataService.php→ ./Business/src/Services/DataService.php
<?php
namespace App\Services;

use GuzzleHttp\ClientInterface;
use GuzzleHttp\Client;
use Psr\Http\Message\ResponseInterface;

/**
 * Cliente HTTP hacia la capa de DATOS.
 *
 * Cambio para despliegue: si existe INTERNAL_KEY en el .env, se envía en la
 * cabecera X-Internal-Key. La capa de datos (cuando también tiene INTERNAL_KEY)
 * rechaza con 403 cualquier petición que no la traiga, de modo que aunque el
 * hosting obligue a que la capa de datos tenga URL pública, solo la capa de
 * negocio puede consumirla. Sin INTERNAL_KEY se comporta igual que antes.
 */
final class DataService {
    private ClientInterface $client;
    public function __construct(object $config) {
        $headers = ['Accept' => 'application/json'];
        $internalKey = $_ENV['INTERNAL_KEY'] ?? '';
        if ($internalKey !== '') {
            $headers['X-Internal-Key'] = $internalKey;
        }

        $this->client = new Client([
            'base_uri' => rtrim($config->api_data, '/') . '/',
            'timeout' => $config->timeout,
            'connect_timeout' => $config->timeout,
            'http_errors' => false,
            'headers' => $headers
        ]);
    }
    public function get(string $path, array $query = []): ResponseInterface {
        return $this->client->request('GET', ltrim($path, '/'),
            ['query' => $query]);
    }
    public function post(string $path, string $body): ResponseInterface {
        return $this->client->request('POST', ltrim($path, '/'),
            ['body' => $body,
             'headers' => ['Content-Type' => 'application/json']
             ]);
    }
    public function put(string $path, string $body): ResponseInterface {
        return $this->client->request('PUT', ltrim($path, '/'),
            ['body' => $body,
             'headers' => ['Content-Type' => 'application/json']
             ]);
    }
    public function delete(string $path): ResponseInterface {
        return $this->client->request('DELETE', ltrim($path, '/'));
    }
}

#!/bin/sh
# ==========================================================================
#  Entrypoint de la capa de DATOS
#  - Ajusta el puerto de Apache a $PORT
#  - Lee la contraseña de BD desde DB_PASSW o desde DB_PASSWORD_FILE (secret)
#  - Escribe el certificado CA de la BD si viene en DB_SSL_CA_PEM
#  - Genera /var/www/html/.env
#  - Si INTERNAL_KEY está definida, Apache solo atiende peticiones que traigan
#    la cabecera X-Internal-Key correcta (la envía la capa de negocio)
# ==========================================================================
set -e

PORT="${PORT:-80}"
sed -ri "s/^Listen [0-9]+/Listen ${PORT}/" /etc/apache2/ports.conf
sed -ri "s/<VirtualHost \*:[0-9]+>/<VirtualHost *:${PORT}>/" /etc/apache2/sites-enabled/000-default.conf

# --- Contraseña de la base de datos -------------------------------------
if [ -z "$DB_PASSW" ] && [ -n "$DB_PASSWORD_FILE" ] && [ -f "$DB_PASSWORD_FILE" ]; then
    DB_PASSW="$(tr -d '\r\n' < "$DB_PASSWORD_FILE")"
fi
# Quita saltos de línea que algunos gestores de secretos agregan al final
DB_PASSW="$(printf '%s' "$DB_PASSW" | tr -d '\r\n')"
INTERNAL_KEY="$(printf '%s' "$INTERNAL_KEY" | tr -d '\r\n')"

# --- Certificado CA del proveedor de BD (Aiven, Azure, etc.) ------------
#  DB_SSL_CA      -> ruta a un archivo .pem ya montado (Render, Cloud Run)
#  DB_SSL_CA_PEM  -> contenido PEM en la variable
#  DB_SSL_CA_B64  -> contenido PEM en base64 (útil en Azure / PowerShell)
CA_FILE=/usr/local/share/db-ca.pem
if [ -n "$DB_SSL_CA_B64" ]; then
    printf '%s' "$DB_SSL_CA_B64" | tr -d '\r\n ' | base64 -d > "$CA_FILE"
    DB_SSL_CA="$CA_FILE"
    DB_SSL="${DB_SSL:-true}"
elif [ -n "$DB_SSL_CA_PEM" ]; then
    printf '%s\n' "$DB_SSL_CA_PEM" | tr -d '\r' > "$CA_FILE"
    DB_SSL_CA="$CA_FILE"
    DB_SSL="${DB_SSL:-true}"
fi

ENV_FILE=/var/www/html/.env
{
    echo "DB_HOST='${DB_HOST:-db}'"
    echo "DB_PORT='${DB_PORT:-3306}'"
    echo "DB_USER='${DB_USER:-root}'"
    echo "DB_PASSW='${DB_PASSW}'"
    echo "DB_NAME='${DB_NAME:-citas_medicas}'"
    echo "DB_SSL='${DB_SSL:-false}'"
    [ -n "$DB_SSL_CA" ] && echo "DB_SSL_CA='${DB_SSL_CA}'"
    [ -n "$DB_SSL_VERIFY" ] && echo "DB_SSL_VERIFY='${DB_SSL_VERIFY}'"
    true
} > "$ENV_FILE"
chown www-data:www-data "$ENV_FILE"
chmod 640 "$ENV_FILE"

# --- Protección de la capa de datos con llave interna -------------------
CONF=/etc/apache2/conf-enabled/zz-internal-key.conf
if [ -n "$INTERNAL_KEY" ]; then
    case "$INTERNAL_KEY" in
        *[!A-Za-z0-9_-]*)
            echo "[datos] ERROR: INTERNAL_KEY solo puede tener letras, números, '_' y '-'" >&2
            exit 1 ;;
    esac
    cat > "$CONF" <<EOF
# Generado por docker-entrypoint.sh: solo la capa de negocio puede consumir la API.
# "GET /" queda libre para los health checks del hosting.
<Directory /var/www/html/public>
    Require expr "req('X-Internal-Key') == '${INTERNAL_KEY}' || %{THE_REQUEST} =~ m#^(GET|HEAD) / HTTP#"
</Directory>
EOF
    echo "[datos] API protegida con X-Internal-Key"
else
    rm -f "$CONF"
    echo "[datos] AVISO: INTERNAL_KEY no definida; la API acepta cualquier petición." >&2
fi

echo "[datos] Escuchando en el puerto ${PORT}; BD: ${DB_HOST:-db}:${DB_PORT:-3306}/${DB_NAME:-citas_medicas}"
exec docker-php-entrypoint "$@"

<?php
use Psr\Container\ContainerInterface;

/*
 * Cambios para despliegue:
 *  - DB_PORT: las BD gestionadas (Aiven, Azure...) usan puertos distintos de 3306.
 *  - DB_SSL / DB_SSL_CA / DB_SSL_VERIFY: las BD en la nube exigen conexión TLS.
 * Con el .env actual (sin esas variables) el comportamiento es el mismo de antes.
 */
$container->set('config_bd', function() {
    return (object) [
        'host' => $_ENV['DB_HOST'],
        'port' => (int) ($_ENV['DB_PORT'] ?? 3306),
        'username' => $_ENV['DB_USER'],
        'password' => $_ENV['DB_PASSW'],
        'database' => $_ENV['DB_NAME'],
        'charset' =>  'utf8mb4',
        'ssl' => filter_var($_ENV['DB_SSL'] ?? false, FILTER_VALIDATE_BOOLEAN),
        'ssl_ca' => $_ENV['DB_SSL_CA'] ?? '',
        'ssl_verify' => isset($_ENV['DB_SSL_VERIFY'])
            ? filter_var($_ENV['DB_SSL_VERIFY'], FILTER_VALIDATE_BOOLEAN)
            : null,
    ];
});

// Opciones PDO para TLS, compartidas por conexion.php y eloquent.php
$container->set('pdo_ssl_options', function(ContainerInterface $c) {
    $conf = $c->get('config_bd');
    if (!$conf->ssl) {
        return [];
    }

    // PHP >= 8.4 usa Pdo\Mysql::*; las constantes PDO::MYSQL_* están obsoletas
    $attrCa = defined('Pdo\Mysql::ATTR_SSL_CA')
        ? \Pdo\Mysql::ATTR_SSL_CA : PDO::MYSQL_ATTR_SSL_CA;
    $attrVerify = defined('Pdo\Mysql::ATTR_SSL_VERIFY_SERVER_CERT')
        ? \Pdo\Mysql::ATTR_SSL_VERIFY_SERVER_CERT : PDO::MYSQL_ATTR_SSL_VERIFY_SERVER_CERT;

    $customCa = $conf->ssl_ca !== '';
    $ca = $customCa ? $conf->ssl_ca : '/etc/ssl/certs/ca-certificates.crt';
    // Con el CA del proveedor se verifica el certificado; sin él solo se cifra.
    $verify = $conf->ssl_verify ?? $customCa;

    return [
        $attrCa => $ca,
        $attrVerify => $verify,
    ];
});

# ==========================================================================
#  Nginx de la capa de PRESENTACIÓN
#  - Sirve la SPA de Angular
#  - Reenvía /api/* a la capa de NEGOCIO (reverse proxy). Así el navegador
#    solo habla con un dominio: no hay CORS ni "mixed content", y la URL de
#    negocio se cambia con una variable de entorno sin recompilar Angular.
#  ${PORT}, ${BUSINESS_URL} y ${NGINX_LOCAL_RESOLVERS} los reemplaza envsubst.
# ==========================================================================
server {
    listen ${PORT};
    listen [::]:${PORT};
    server_name _;

    root  /usr/share/nginx/html;
    index index.html;

    # DNS dinámico: la IP de la capa de negocio puede cambiar en el hosting
    resolver ${NGINX_LOCAL_RESOLVERS} valid=30s ipv6=off;
    set $business ${BUSINESS_URL};

    location /api/ {
        proxy_pass $business;
        proxy_http_version 1.1;
        proxy_ssl_server_name on;
        proxy_set_header Host              $proxy_host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 75s;
        proxy_read_timeout    90s;
    }

    # Archivos con hash de Angular: caché larga
    location ~* \.(?:js|css|woff2?|ttf|svg|png|jpg|jpeg|gif|ico|webp)$ {
        try_files $uri =404;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # Rutas del router de Angular -> index.html
    location / {
        try_files $uri $uri/ /index.html;
        add_header Cache-Control "no-cache";
    }

    gzip on;
    gzip_types text/plain text/css application/json application/javascript image/svg+xml;
}
